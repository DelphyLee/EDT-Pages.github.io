# 管理面板与 Worker：项目关系和发布约定

## 项目边界

- EDT-Pages.github.io：维护 GitHub Pages 上的管理面板静态界面。
- EdgeTunnel-ExitProxy：维护 Worker 源码、配置接口、运行逻辑和 Cloudflare Pages ZIP。
- Cloudflare Pages magictunnel：实际运行 Worker。
- EdgeTunnel：旧源码和提取副本归档，不再作为维护或打包入口。

两个源码项目保持独立仓库，通过接口契约和本文档关联；不复制对方源码，也不使用 Git 子模块。

## 运行时接口

Worker 从 GitHub Pages 读取管理面板 HTML。页面在 Worker 域名下运行时，以下接口由 Worker 处理：

- GET/POST /admin/config.json：读取或保存配置；生产配置写入 Cloudflare KV。
- GET /admin/log.json：读取 Worker 运行日志。

因此，GitHub Pages 仓库只需要发布面板 HTML 和静态资源；不能保存真实生产配置或日志。页面工作流目前按整个仓库根目录发布，所有被跟踪的文件都会成为静态发布内容。

## 版本兼容

- 面板从 Worker `/version` 接口读取版本并控制兼容功能：ALPN 控件要求 Worker 版本不低于 `20260904162413` 且配置中存在 `ALPN` 字段；连接复用（XMUX）控件要求 Worker 版本不低于 `20261110232646` 且配置中存在 `连接复用` 字段。
- 当前配套 Worker Version 为 `2026-11-10 23:26:46`（`20261110232646`）；管理面板已同步至 `EDT-Pages/EDT-Pages.github.io` `aaab6db`，采用上游官方 ALPN / ECH×指纹冲突 / `EXPAND` 开关 / XMUX 弹窗，并与本地 PROXYIP 池、预设域名下拉、获取更多 PROXYIP 及出口规则融合。
- 仅汇聚订阅 User-Agent 等 Worker 内部行为变化，不要求更新面板；涉及配置字段新增（如 XMUX）时，需先部署兼容 Worker，再发布面板。

## 发布流程

| 变化范围 | 更新位置 | 发布动作 |
|---|---|---|
| 面板样式或交互 | EDT-Pages.github.io | 推送 main，等待 GitHub Pages 完成发布，再从 Worker 域名检查 /admin |
| Worker 逻辑或配置默认值 | EdgeTunnel-ExitProxy | 重新打包 ZIP，上传 Cloudflare Pages magictunnel，并检查 Worker /version |
| Worker 与面板接口契约 | 两个项目 | 先发布向后兼容的 Worker，再发布面板；分别验证接口和 UI |

## 静态发布数据边界

GitHub Pages 是公开静态站点。不要提交真实 UUID、订阅 token、Cloudflare/Telegram 凭据、用户配置或运行日志。生产配置与运行数据只由 Worker API 从 Cloudflare KV 返回。

admin/config.json 和 admin/log.json 如用于本地演示，只能使用虚构、脱敏数据，并保持在 Git 跟踪之外。每次 Pages 发布前确认 GitHub Actions artifact 不包含运行数据或秘密。

如果真实配置或日志曾进入 Git 历史或 Pages 发布内容，应把其中的凭据按已暴露处理并立即轮换；访问日志也应按公开数据评估。删除当前文件并重新发布不会清除旧提交中的内容。需要清除历史副本时，必须协调重写 Git 历史并更新其他克隆；优先先轮换凭据。
